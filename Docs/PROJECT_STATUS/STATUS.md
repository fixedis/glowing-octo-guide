## 3. КАСЯКИ и известные проблемы

> Приоритет: 🔴 критично / 🟠 важно / 🟡 мелочь. Отмечай `[x]` когда пофикшено.

### 3.1 Документация (из `REMARKS.md`)
- [ ] 🟡 `REMARKS.md` п.6: `SnapshotManager::hashState()` делает `json_encode($state)` **без `ksort`** → хэш снапшота зависит от порядка вставки ключей. Ломает детерминизм replay/сетевую синхронизацию. Фикс: `ksort($state)` перед encode.
- [ ] 🟡 `module-guide.md` правило 5 (и п.7): китайские иероглифы `随机数` вместо «случай» (опечатка кодировки).
- [ ] 🟡 `architecture.md` («Текущие ограничения»): не упоминает `CombatEngine/FleetEngine/ProductionEngine` как реализованные (устарело после роадмапа).

### 3.2 Сервер — баги/расхождения
- [ ] 🟡 `CombatEngine/Core/Commands/ResolveCombatHandler.php:116`: `new Event(sprintf('combat_resolved_%s', $command->id), 'CombatResolved', ...)` — первый аргумент это `id`, второй `type`. `id` выглядит как тип. Функционально ок (фильтрация по `type`), но стоит причесать `id`.
- [ ] 🟠 `CombatEngine`: списывает «боеприпасы» (`ammoCost`) из `economy.colony.*.stored`. В FAQ боеприпасы в бою **бесконечны**, газ тратится только на прыжки. Временная натяжка — переделается при реализации боя.
- [ ] 🔴 **Разрыв production→universe**: произведённые здания (`ProduceBuilding`) пишутся в `production.colony.*.buildings[]`, но **не попадают** на `ColonyGrid`/`BuildingDeltaStore` (UniverseEngine). Здания на планете и юниты в производстве — параллельные вселенные.
- [ ] 🟠 `FleetEngine` типы флотов (`exploration/transport/strike`) **не совпадают** с FAQ (классы корвет/крейсер/линкор/титан + режимы бомбардировка/бой/следование/стоянка).
- [ ] 🟠 `FleetEngine::MoveFleetHandler` = **телепорт** (смена координат), без скорости/газа/движения по туннелям.

### 3.3 Клиент
- [ ] 🟡 `client/src/app/universe-app.ts`: много `TEMP`/`TEMP DEBUG` (debug-панель фильтров, `__uni`, `#dbg`). Убрать перед релизом.
