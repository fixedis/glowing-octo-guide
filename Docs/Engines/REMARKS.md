# Замечания по реализованным движкам (UniverseEngine + NaniteEngine + экосистема)

Автор: инженерный ассистент. Цель — зафиксировать расхождения с документацией
проекта и потенциальные риски. Код менять не предлагаю без явной команды;
здесь — что и почему стоит поправить в **документации** и на что обратить внимание.

> **Статус (актуально на момент проверки):** реализованы UniverseEngine,
> NaniteEngine, EconomyEngine, NetworkEngine, AdminEngine + persistent runtime.
> Пункты 1 и 3 ниже **закрыты** (docs обновлены, UniverseRouter помечен
> DEPRECATED, NetworkEngine вынесен). Оставлены как история решения.

о существующих движках.

## 2. RNG: движки нарушают «букву» правила `AI/rules.md` §10

Правило: «движок должен использовать `DeterministicRandomInterface`».

- `UniverseEngine` использует **собственный** `SeedGraph` (FNV-1a + mulberry32).
- `NaniteEngine` RNG не использует вовсе (чистые функции от входа).

**Почему это, вероятно, сознательно:** `SeedGraph` побайтово синхронизирован с
TypeScript-клиентом (тот же алгоритм mulberry32, тот же порядок потребления RNG).
Замена на SHA-256-вар ядра (`DeterministicRandom`) **сломала бы клиентскую
синхронию** спиралей/планет. То есть текущая реализация корректна по духу
(детерминизм соблюдён), но противоречит букве правила.

**Действие:** смягчить правило в `AI/rules.md` §10 до «движок использует
детерминированный RNG; собственный RNG допустим только при обоснованной
синхронизации с клиентом (как `SeedGraph`)».

---

## 3. HTTP-слой внутри движка противоречит «сеть отделена» — РЕШЕНО ✅

`AI/rules.md` и `architecture.md`: «сеть — подключаемый модуль». Ранее
`UniverseEngine/Presentation/` содержал `UniverseRouter` + `HttpRequest::fromGlobals()`.

**Решение:** HTTP-слой вынесен в `NetworkEngine` (`NetworkRouter`) — единый фасад
`/api/v1/*` для всех движков. `UniverseRouter` помечен **DEPRECATED** (исторический
артефакт + тесты обратной совместимости), `index.php` использует `NetworkRouter`.
Техдолг закрыт (см. `Docs/Engines/NetworkEngine.md`, `architecture.md`).

**Смягчающие факты (исторические):**
- Router state не меняет — только диспатчит команды через `CommandBus`.
- Конструктор принимает `HttpRequest` (тестируемо, без SAPI-привязки в логике).

**Риск:** при появлении выделенного `NetworkEngine` HTTP-маршрутизацию придётся
выносить. Сейчас это техдолг, а не баг.

**Действие (на выбор):** либо задокументировать `Presentation/` как «внутренний
модуль презентации, допустимый до появления NetworkEngine», либо заложить
вынос в «Будущие расширения».

## 4. Float в генерации контента

`numeric-infrastructure.md`: «критичная симуляция не использует float».
Генераторы UniverseEngine активно используют float (`mulberry32` возвращает
float, `cos/sin/pow`, `rng() * N`).

**Оценка:** генерация контента ≠ боевая симуляция. Детерминизм от IEEE-754
стабилен, порядок RNG выровнен с TS. Риск только при расхождении порядка
float-операций PHP↔TS (авторы это учли, зафиксировав порядок потребления).
Не требует правки, но стоит упомянуть в доке, чтобы не путать с «симуляцией».

---

## 5. Формулировка про «вложенные пути сущностей» неточна

`architecture.md` («Текущие ограничения»): «Вложенные пути сущностей пока не
поддерживаются без явного namespace».

**Факт из кода:** `EntityDiscovery::discover()` бросает `RuntimeException`,
только если само поле `path` в манифесте содержит `/` (например `"Entities/Planets"`).
Внутренняя `scanPhpFiles()` обходит директорию **рекурсивно** и собирает все
`.php` в подпапках. Поэтому манифест UniverseEngine с `"path": "Entities"` +
реальными `Entities/Planets/Planet.php` работает легально.

**Действие:** переформулировать ограничение как «поле `path` в манифесте —
одноуровневое; иерархия внутри папки `entities` сканируется рекурсивно».

## 6. Hash снапшота зависит от порядка ключей state

`SnapshotManager::hashState()` делает `json_encode($state)` без `ksort`.
Порядок ключей в `State::$data` = порядок вставки. Если в разные тики ключи
добавляются в разном порядке, хэш снапшота будет разным при одинаковом составе.

**Влияние:** симуляцию не ломает, но может ломать детерминизм хэша при
восстановлении/реплее/сетевой синхронизации (будущие фичи).

**Действие (низкий приоритет):** добавить `ksort($state)` перед `json_encode`
в `hashState()`, либо зафиксировать, что порядок вставки детерминирован.
